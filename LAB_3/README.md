## 3. Настройка Ansible

### 3.1. Создание конфигурационного файла

В корневой директории проекта был создан файл `ansible.cfg` со следующим содержимым:

```ini
[defaults]
host_key_checking = false
inventory = inventory/hosts
```

Данный файл определяет основные параметры Ansible:
- `host_key_checking = false` — отключает проверку SSH host key.
- `inventory = inventory/hosts` — указывает путь к файлу инвентаризации.

### 3.2. Настройка Inventory

Была создана директория `inventory` и файл `hosts`:

```bash
mkdir -p inventory
```

Содержимое файла `inventory/hosts`:

```ini
[my_servers]
local_server ansible_host=localhost
```

В лабораторной работе используется локальное выполнение команд в Ubuntu WSL2. Поэтому для Playbook применяется параметр `connection: local`.

### 3.3. Проверка подключения

Для проверки доступности узла была выполнена команда:

```bash
ansible my_servers -m ping -c local
```

## 5. Выполнение задания 2. Создание Role для установки Caddy

### 5.1. Создание структуры Role

Для автоматизации установки и настройки веб-сервера была создана Ansible Role с именем `caddy_deploy`.

Команда создания Role:

```bash
ansible-galaxy init roles/caddy_deploy
```
(16)

Основные файлы проекта:

```text
ansible-caddy-lab/
├── ansible.cfg
├── inventory/
│   └── hosts
├── caddy_deploy.yml
├── file_operations.yml
└── roles/
    └── caddy_deploy/
        ├── files/
        │   └── index.html
        ├── tasks/
        │   └── main.yml
        ├── templates/
        │   └── Caddyfile.j2
        └── vars/
            └── main.yml
```
(17)
### 5.2. Настройка переменных Role

В файле `roles/caddy_deploy/vars/main.yml` определены переменные:

```yaml
---
site_address: ":8080"
web_root: /var/www/hello-world
log:
  file: /var/log/caddy/access.log
  level: "INFO"
```

Назначение переменных:

- `site_address` — адрес и порт веб-сервера.
- `web_root` — директория с файлами сайта.
- `log.file` — путь к файлу журнала доступа.
- `log.level` — уровень журналирования.

### 5.3. Настройка установки Caddy

В файле `roles/caddy_deploy/tasks/main.yml` определены задачи автоматизации установки и настройки Caddy.

Основные этапы:

1. Обновление списка пакетов APT.
2. Установка необходимых зависимостей.
3. Добавление официального GPG-ключа репозитория Caddy.
4. Добавление официального репозитория Caddy.
5. Установка веб-сервера Caddy.
6. Создание директории для файлов сайта.
7. Копирование собственной HTML-страницы.
8. Создание директории для журнала доступа.
9. Создание файла журнала с необходимыми правами доступа.
10. Генерация конфигурационного файла Caddy.
11. Проверка корректности конфигурации.
12. Включение и перезапуск службы Caddy.

Для установки и настройки используются модули Ansible, в том числе `apt`, `get_url`, `command`, `file`, `copy`, `template` и `service`.

### 5.4. Создание основного Playbook

В корневой директории проекта был создан файл `caddy_deploy.yml`:

```yaml
---
- name: Install and configure Caddy webserver
  hosts: my_servers
  connection: local
  become: true
  roles:
    - caddy_deploy
```

Playbook подключает Role `caddy_deploy` и выполняет ее задачи на локальном узле с правами суперпользователя.

### 5.5. Проверка синтаксиса и запуск

Перед запуском была выполнена проверка синтаксиса:

```bash
ansible-playbook --syntax-check caddy_deploy.yml
```

После успешной проверки был запущен Playbook:

```bash
ansible-playbook caddy_deploy.yml --ask-become-pass
```

Для копирования HTML-файла на сервер используется задача Ansible с модулем `copy`.

Файл размещается в директории:

```text
/var/www/hello-world
```

Таким образом, при запуске Playbook HTML-страница автоматически копируется в корневую директорию сайта.

### 6.3. Настройка Caddyfile с использованием Jinja2

Для автоматической генерации конфигурации был создан шаблон:

`roles/caddy_deploy/templates/Caddyfile.j2`

Содержимое шаблона:

```caddyfile
{{ site_address }} {

    root * {{ web_root }}

    encode gzip zstd

    header {
        X-Content-Type-Options "nosniff"
        X-Frame-Options "DENY"
        Referrer-Policy "strict-origin-when-cross-origin"
    }

    log {
        output file {{ log.file }}
        format json
        level {{ log.level }}
    }

    file_server
}
```

В конфигурации реализованы следующие функции:

- Обслуживание статических файлов сайта.
- Сжатие HTTP-ответов с помощью Gzip и Zstandard.
- Добавление HTTP-заголовков безопасности.
- Запись журнала доступа в формате JSON.
- Настройка корневой директории сайта.

Для генерации итогового файла используется модуль `template`.

### 6.4. Дополнительные настройки

Для корректной работы Caddy была создана директория журнала:

```text
/var/log/caddy
```

Директории и файлу журнала назначены необходимые права доступа для пользователя и группы `caddy`.

Это необходимо, поскольку служба Caddy работает от имени пользователя `caddy` и должна иметь возможность записывать информацию в журнал.

После генерации конфигурации выполняется ее проверка, а затем служба Caddy перезапускается.
